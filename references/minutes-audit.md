# 纪要核验与修订配方（AI 纪要 × 逐字稿反查 → v2）

适用：已有一份《专家访谈纪要汇总》（AI 生成或他人执笔），要与逐字稿逐条核对「①编造伪造 ②内容无法对齐 ③遗漏重要内容」，然后出 v2、其他内容不变。

## 1. 定事实源

| 材料 | 能否当事实源 | 说明 |
|---|---|---|
| `公司（逐字稿）` 合并稿 | ✅ 唯一基准 | 通篇 `采访者：/专家：`，无摘要、无重复段 |
| 各场原始 docx 的 `2. AI对话列表` | ⚠️ 定位辅助 | 与逐字稿同源、带时间戳，可定位到分钟 |
| 各场原始 docx 的 `1. 会议摘要` | ❌ | AI 二手摘要，本身带 ASR 错字与漏项 |

用合并逐字稿：切一次、五路并行共用，行号可直接复用到交付清单。

## 2. 抽文本与切分

```bash
/usr/bin/python3 scripts/split_sections.py "…访谈逐字稿汇总.docx" _build/txt --mode 逐字稿
/usr/bin/python3 scripts/split_sections.py "…访谈纪要汇总.docx"   _build/txt --mode 纪要
```

输出每行 `行号|[样式名] 文本`，行号与 `read_file` 显示一致——子代理引用证据直接写 `L123`，交付清单能一键回查。逐场成对喂给子代理（两边的节序一致）。

喂之前先给纪要段生成「高风险数字清单」：把带单位的数字抄成一句（`2.4-2.6亿台 / 55-58寸 / 8-12颗 / 0.3-0.5美金 / 毛利15个点`），塞进 context 逼子代理逐个回原文核。数字是最容易被 AI 编的一类。

## 3. 一路一场并行核查

每路 context 五件套：①该场纪要段路径 ②该场逐字稿段路径 ③`references/cof-noun-map.md` 的映射表**原文**（别只给路径）④「`【待核】` 是编稿时的主动标注，不算错误」⑤A/B/C 定义 + 输出 schema。

```json
findings: [{type: A|B|C, location: "章节+小节+第几条", current: "纪要原句",
            should_be: "具体改法或补入内容", evidence: "逐字稿原句 + L123", severity: 高|中|低}]
verified_ok: ["核过没问题但极关键的数字/判断"]
```

要求写死在 goal 里：`逐条对照、不抽样`；`原句照抄含 ASR 错字`；`证据不足写「建议回听」，不要猜`；1000 行以上的逐字稿要 `offset/limit` 分页读完。

## 4. 三类判定口径

- **A 编造**：逐字稿无对应语句。高发形态是「纪要替专家补了原因/机制」——原文只描述现象，纪要写成「因为…所以…」。
- **B 无法对齐**：有对应语句但数字、主体（哪家公司说的）、时间、方向不一致；或把「大概/我记得/印象中」写成确定口径。
- **C 遗漏**：逐字稿有、且影响尽调判断（供需数字、价格成本、客户绑定、扩产与出清时间表、标的评价、认证周期、良率、进入门槛），纪要未体现或明显弱化。只报重要项，不报闲聊与口头语。
- 判 A 之前先 grep 变体，否则会把 ASR 转写差异报成伪造。

## 5. 主代理回验（必做）

子代理清单是自述不是事实。每条 A/B 至少抽一条证据回原文 grep 核行号与措辞，优先抽数字、公司名、方向性判断（谁主导 / 谁付钱 / 谁退得快）。抽查不过的那一路整路降级重跑。

## 6. 出 v2（就地改，其他内容不变）

```python
import docx, copy
from docx.text.paragraph import Paragraph
d = docx.Document("…纪要汇总 v2.docx")        # 先 cp 原件改名，绝不动源文件
p = [x for x in d.paragraphs if x.text.startswith("待改段开头")][0]
p.runs[0].text = "新表述（改前：旧表述）"       # 1 段 1 run：换 text 即保留 rPr
new = copy.deepcopy(p._p); p._p.addnext(new)    # 插条：克隆邻段保 numPr/缩进
Paragraph(new, p._parent).runs[0].text = "新增条目"
p._p.getparent().remove(p._p)                   # 删条：倒序执行
```

- 批量前跑 **no-op roundtrip**（克隆→插→删→save→读回段落总数不变），确认机制成立。
- 读回验收：段落总数、每条新文本命中 ≥1、旧错词计数 = 0、`【待核】` 计数符合预期、`zipfile.testzip()` 为 None。

## 7. 交付

- 聊天里给分级清单：`A1 现文 → 应为 → 依据（逐字稿 L123）`；末尾单列「核对无误的关键数字」（来自 `verified_ok`）与「建议补的数」。
- 文件 `MEDIA:` 发 v2，说明基于哪一版、动了多少条、哪些条目等他批。
- 他按条批；未批的条目不要自行改。
